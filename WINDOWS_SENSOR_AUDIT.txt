RATIONALE:
──────────
1. SIMPLICITY: No kernel driver needed, no feature flags, no registry magic
2. SYSMON AVAILABLE: Most enterprise deployments have Sysmon running already
3. SECURITY LOG: Always present; can be read without elevation if auditing enabled
4. STABILITY: Event Logs are stable, bounded, and have cursor support
5. COVERAGE: Sysmon covers process/network/file/injection/LSASS (events 1,3,7-11,10,etc.)

WHAT GETS ALWAYS-ON:
─────────────────────
✓ Sysmon Event Log subscription (Application & Services Logs > Microsoft-Windows-Sysmon)
  - Events: 1 (process), 3 (network), 7 (image load), 10 (LSASS access), 11 (file create),
            13 (registry set), 22 (DNS), 26 (file delete)
✓ Security Event Log (critical events only)
  - Events: 4624 (successful logon), 4625 (failed logon), 4688 (process creation),
            4728 (group member add), 4657 (registry value modified), 1102 (log cleared)

WHAT STARTS DISABLED (enable via env var):

○ TaskScheduler/Operational (106/140: task create/update)
○ Registry monitor (Sysmon 12/13/14)
○ Defender adapter (when available via EVTX or API)
○ ETW (requires elevation and cfg feature)

   File: windows/config.rs

   - Work budgets: max_parse_errors_per_poll
   - Env vars: EDR_WIN_<SOURCE>_<SETTING>=value
   - Defaults: Sysmon=enabled, Security=enabled, Others=disabled

B. ENHANCE EVTX COLLECTOR
   - Add EvtxReader struct with bookmark/cursor tracking
   - Implement poll_and_convert() method that:
     * Reads up to max_records_per_poll events from bookmark
     * Updates bookmark after successful parse
     * Returns (events, parse_failed_count, bookmarks_state)
   - Track per-source metrics: last_event_ts, events_read_total, parse_failed_total
   - Emit sensor_health if parse errors exceed threshold

C. IMPLEMENT POLLING LOOP IN CAPTURE
   - capture_windows_rotating::poll_and_write():
     * Call evtx_collector.poll() for each log (Sysmon, Security, etc.)
     * Collect return events
     * Assign EvidencePtr at write time (stream_id = "evtx:Sysmon", segment_id, record_index)
     * Sort deterministically
     * Write to rotating JSONL segment
     * Emit heartbeat with transport="evtx", events_read, parse_failures, last_event_ts

D. HEARTBEAT METRICS
   - Every 5 seconds, write heartbeat.json:
     {
       "ts": "2025-12-22T12:34:56Z",
       "transport": "evtx",
       "source": "Sysmon",
       "events_read_total": 1234,
       "events_read_delta": 15,
       "parse_failed_total": 2,
       "parse_failed_delta": 0,
       "last_event_ts": "2025-12-22T12:34:50Z",
       "status": "healthy"
     }

E. ERROR TRANSPARENCY
   - If EvtxCollector can't open a log, emit ONE sensor_health event and continue
   - Use rate limiting to avoid spam
   - Don't crash; degrade gracefully
