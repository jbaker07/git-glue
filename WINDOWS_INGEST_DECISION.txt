WINDOWS DEFAULT INGEST PATH: DECISION + IMPLEMENTATION PLAN
December 22, 2025

OPTION ANALYSIS
────────────────────────────────────────────────────────────────────────────────

OPTION 1: WEVTAPI EvtSubscribe (Recommended ✓)
─────────────────────────────────────────────
HOW: Real-time event log subscription using Windows Event Log API
PROS:
  ✓ Stable, well-documented Windows API
  ✓ Real-time events (no polling latency)
  ✓ Bookmark support (native, no custom tracking needed)
  ✓ Covers all channels: Sysmon, Security, System, PowerShell, WMI, TaskScheduler
  ✓ Single channel can emit many event types (cheaper than polling all)
  ✓ Can filter at subscription time (XPath query reduces noise)
  ✓ Works with elevation on enterprise systems (standard deployment)
CONS:
  - Requires elevation (run as Administrator or NT AUTHORITY\SYSTEM)
  - More complex setup than polling
  - Thread-based (needs callback management)
DEPLOYMENT: Standard on enterprise Windows; typical EDR runs elevated anyway

OPTION 2: EVTX Polling with Bookmarks (Fallback ○)
────────────────────────────────────────────────────
HOW: Periodic polling of Event Log with bookmark resumption
PROS:
  ✓ Works with lower privilege levels
  ✓ Simpler synchronous polling loop
  ✓ Easier to test (no async/threading complexity)
  ✓ Bounded work per poll (controllable)
CONS:
  - Latency: events arrive 100-1000ms after creation
  - Polling overhead: re-query even if no new events
  - More bookmark complexity (manual tracking)
DEPLOYMENT: Fallback for non-elevated scenarios; secondary to subscription

OPTION 3: ETW (Not Recommended for Always-On)
──────────────────────────────────────────────
HOW: Event Tracing for Windows kernel-level tracing
PROS:
  ✓ Low overhead
  ✓ Real-time kernel events
CONS:
  - Requires elevation + feature gate
  - Kernel provider registration complex
  - Session management required
  - Non-SYSTEM processes can't read kernel traces reliably
DEPLOYMENT: Optional enhancement for specific scenarios; not critical path

═══════════════════════════════════════════════════════════════════════════════

DECISION: OPTION 1 (WEVTAPI EvtSubscribe) AS PRIMARY
         OPTION 2 (EVTX Polling) AS FALLBACK
────────────────────────────────────────────────────────────────────────────────

WHY:
  - Event Log subscription is THE standard Windows logging API
  - Native bookmark support (no custom state tracking needed)
  - Covers 100% of required channels (Sysmon, Security, System, PowerShell, WMI, TaskScheduler)
  - Real-time (no polling latency)
  - Enterprise standard (EDR runs elevated)
  - Simple to reason about: "subscribe → get events → process → bookmark moves forward"

FALLBACK LOGIC:
  - If EvtSubscribe fails (low privilege, API unavailable), fall back to EVTX polling
  - Emit health event: "Windows Event Log subscription unavailable, using polling fallback"
  - Same to_canonical_event() logic works for both (events are identical)

STEP 1: Create windows/sensors/evtx_reader.rs (NEW, ~300 lines)
──────────────────────────────────────────────────────────────

Struct EvtxReader {
  channels: Vec<String>,    // "Microsoft-Windows-Sysmon/Operational", etc.
  subscriptions: HashMap<String, HEVENTXUBSCRIPTIONHandle>,  // keyed by channel
  last_event_ts: HashMap<String, DateTime<Utc>>,
  events_read_total: HashMap<String, u64>,
  parse_failed_total: HashMap<String, u64>,
  max_records_per_poll: u64,
}

impl EvtxReader {
  pub fn new(channels: Vec<&str>, max_records_per_poll: u64) -> Result<Self, EvtxError>
    - For each channel, call EvtSubscribe() with XPath filter for relevant event IDs
    - Store handle in subscriptions
    - Return Self with empty metrics

  pub fn poll(&mut self) -> Result<(Vec<crate::Event>, EvtxMetrics), EvtxError>
    - For each subscription:
      - Call EvtNext(hSubscription, ...) to fetch up to max_records_per_poll events
      - For each event:
        - Call RenderEvent() to get XML
        - Parse XML to EvtxRecord
        - Call EvtxCollector::to_canonical_event() to convert
        - Collect event + update metrics
      - Handle errors (log cleared, lost records, etc.)
    - Return (events, metrics) where metrics include per-channel stats

  pub fn close(&mut self)
    - Close all subscriptions
}

Also implement:
  struct EvtxError { ... }
  struct EvtxMetrics { events_per_channel: BTreeMap<String, u64>, ... }
  Bindings to winapi: EvtSubscribe, EvtNext, RenderEvent, EvtClose, etc.

STEP 2: Wire evtx_collector.poll()
────────────────────────────────────
Replace:
  pub fn poll(...) -> PollResult {
    #[cfg(not(target_os = "windows"))] { return empty }
    #[cfg(target_os = "windows")] {
      eprintln!("not implemented");
      return empty;
    }
  }

With:
  pub fn poll(
    &mut self,
    _stream_id: &str,
    _segment_id: &str,
    _max_records: u64,
  ) -> PollResult {
    let mut events = Vec::new();
    let mut parse_failed = 0;
    let mut last_ts = None;

    #[cfg(target_os = "windows")]
    {
      if self.reader.is_none() {
        self.reader = EvtxReader::new(
          self.enabled_logs.iter().map(|s| s.as_str()).collect(),
          _max_records,
        ).ok();
      }
      
      if let Some(reader) = &mut self.reader {
        match reader.poll() {
          Ok((polled_events, metrics)) => {
            for evt in polled_events {
              if let Some(canonical) = self.to_canonical_event(&evt) {
                events.push(canonical);
                if let Some(ts) = last_ts {
                  last_ts = Some(std::cmp::max(ts, evt.ts));
                } else {
                  last_ts = Some(evt.ts);
                }
              } else {
                parse_failed += 1;
              }
            }
            self.last_metrics = metrics;
          }
          Err(e) => {
            eprintln!("[evtx_collector] poll error: {:?}", e);
            parse_failed += 1;
          }
        }
      }
    }

    PollResult {
      events,
      parse_failed_count: parse_failed,
      last_record_ts: last_ts,
    }
  }

  pub fn poll_and_write(&mut self) -> Result<()> {
    let events = windows::sensors::collect_all(&self.host, &self.config);
    
    // Assign EvidencePtr at write time
    for evt in &mut events {
      if evt.evidence_ptr.is_none() {
        evt.evidence_ptr = Some(EvidencePtr {
          stream_id: "evtx:Windows".to_string(),
          segment_id: self.current_segment_id.clone(),
          record_index: self.record_index,
        });
        self.record_index += 1;
      }
    }
    
    // Write to segment + update heartbeat
    self.write_segment(events)?;
    self.emit_heartbeat()?;
    Ok(())
  }

STEP 5: Bookmark Persistence

Create windows/telemetry/bookmarks.json:
  {
    "Microsoft-Windows-Sysmon/Operational": "base64-encoded-bookmark-xml",
    "Security": "...",
    "System": "...",

On startup: Load bookmarks.json, pass to EvtxReader
On each successful poll: Update bookmarks.json with new state
Ensures: Never lose events, never re-read old events across restarts

FALLBACK TO EVTX POLLING (if EvtSubscribe fails)
═════════════════════════════════════════════════════════════════════════════

If EvtSubscribe() returns ERROR_ACCESS_DENIED or similar:
  1. Emit ONE sensor_health event: "Event Log subscription failed, falling back to polling"
  2. Create EvtxPoller (alternative to EvtxReader)
  3. Same interface: pub fn poll() -> Result<(Vec<Event>, Metrics)>
  4. Uses EvtQuery + EvtNext + bookmark tracking manually
  5. All to_canonical_event() logic remains identical
  6. Difference: latency ~500ms instead of real-time

Fallback is transparent: capture_windows_rotating doesn't care which reader is used.

   - Create test process: powershell.exe "Get-Help"
