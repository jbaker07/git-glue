═══════════════════════════════════════════════════════════════════════════════
KEY DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════════════════

1. ALWAYS-ON SET: Sysmon + Security + System (not ETW or Defender)
   - Rationale: Most deployments have Sysmon; Security log is universal
   - ETW requires elevation + feature gate; Defender may not be present
   - This is conservative, stable, and deployable everywhere

2. CONFIG GATING PATTERN: Parallel to linux/sensors_v2/config.rs
   - Consistency across platforms
   - Per-source control (don't need to recompile)
   - Env vars make testing easy

3. POLLING LOOP: Bounded work, metrics tracking, graceful degradation
   - Not async (simple, testable, deterministic)
   - Not spawning threads (capture owns the loop)
   - Heartbeat emits per-source (visibility into each log health)

4. EVENT LOG BOOKMARK PLACEHOLDER
   - Real implementation on Windows would use WEVTAPI bookmarks
   - Current poll() returns empty (feature-gated)
   - Structure is ready for real bookmarking logic
